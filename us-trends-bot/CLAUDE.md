# CLAUDE.md

Інструкції для Claude Code щодо цього репозиторію.

## Що це

Щоденний Telegram-дайджест трендів США. Англомовні джерела (Google Trends `geo=US`, Google News US, музичні й культурні медіа), дайджест пишеться українською. Генерує Gemini API, запускає GitHub Actions. Створено на основі `YaroslavChess/ua-trends-bot`.

## Структура

* `trends_digest.py` — єдиний скрипт: `FEEDS` → `fetch_entries` (фільтри, квоти) → `build_prompt` → `call_gemini_api` → `send_telegram` → `save_sent`.
* `.github/workflows/trends_digest.yml` — розклад, «сторож» часу (крок `gate`), запуск скрипта, коміт `sent.json`.
* `sent.json` — історія надісланого за 14 днів. Пише лише бот у бойовому режимі, вручну не редагувати.
* `requirements.txt` — `feedparser`, `requests`. Нових залежностей без потреби не додавати.

## Жорсткі правила

1. **Жодних секретів у репозиторії.** Ключі й токени лише в GitHub Secrets і лише через `os.environ`: `GEMINI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_TEST_CHAT_ID`, `GEMINI_MODEL`. Не вписувати їх у код, README, воркфлоу, `sent.json` чи приклади. Не друкувати їх у лог.
2. Ключ Gemini передається лише заголовком `x-goog-api-key`, не в URL.
3. Усе, що виводиться в лог з тексту помилок чи відповідей API, проходить через `redact()`.
4. Мова дайджесту — українська; мова джерел і запитів Google News — англійська (`hl=en-US&gl=US&ceid=US:en`).
5. Модель не вигадує: усе в пості береться із записів. Єдина вигадана рубрика — «Питання для нас на вечір». Не послабляти це в промпті.
6. Не додавати політику США й тяжкі теми назад: вони відсіюються стоп-словами за дизайном.

## Час відправки: 08:00 за Києвом

Cron у GitHub лише UTC, тому в воркфлоу два розклади (`0 5` і `0 6`), а крок `gate` перевіряє `TZ=Europe/Kyiv date +%H` і пропускає запуск, якщо година не `08`. Перевірка діє лише для `schedule`, ручний `workflow_dispatch` проходить завжди. Якщо міняєте час, змінюйте обидва cron і число в `gate` разом.

## Стоп-слова (`STOP_PREFIXES`, `STOP_WHOLE_WORDS`, `STOP_ABBREVIATIONS`, `STOP_EXCEPTIONS`)

* `STOP_PREFIXES` — збіг на початку слова без урахування регістру (`shooting`, `senat`).
* `STOP_WHOLE_WORDS` — лише ціле слово (`war`, `dead`, `killed`), інакше буде хибне спрацювання на `warm`, `Warner`.
* `STOP_ABBREVIATIONS` — лише великі літери й ціле слово (`ICE`, `GOP`), щоб `Ice Spice` проходило.
* `STOP_EXCEPTIONS` — вирази, які вирізаються перед перевіркою (`Star Wars`, `The Walking Dead`, `killed it`).
* Додаючи слово, перевіряйте хибні спрацювання на реальних заголовках: назви фільмів, ігор, гуртів, сленг.

## Як перевіряти зміни

Тестового набору немає. Після змін у фільтрах чи парсерах:

1. Прогнати `is_depressing()` на списку «має відсіятись» і «має пройти» (див. приклади в стоп-слів вище).
2. Прогнати `parse_trends()` на невеликому XML із `ht:approx_traffic` і `ht:news_item`.
3. Замокати `requests.get/post` і викликати `main()`, щоб перевірити весь потік без мережі.
4. Для реальної перевірки запустити воркфлоу вручну (**Actions → Run workflow**, прапорець `test` увімкнений): `sent.json` не оновиться, повідомлення піде в тестовий чат.

## Відомі обмеження

* RSS-адреси Billboard, Pitchfork, Stereogum, Variety, Vulture, The Verge, Know Your Meme позначені `unverified`: їх не вдалося відкрити під час створення. Після першого запуску звірити HTTP-статуси в лозі й виправити адреси, що не відповіли.
* Cron GitHub може запізнюватись; запуск, що запізнився більш ніж на годину, у цей день пропускається «сторожем».
* Тон промпту (турботливий хлопець пише дівчині) успадковано з `ua-trends-bot`. Змінюється лише в `build_prompt()`.
