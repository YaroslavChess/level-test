# CLAUDE.md

Тест «Безкоштовна діагностика рівня» для сайту шахової школи yaroslavchess.com.
Аудиторія: українські батьки за кордоном із дітьми 6–14 років і дорослі; більшість батьків
не грає в шахи. Публікація — GitHub Pages з кореня репозиторію (гілка `main`, адреса
`https://yaroslavchess.github.io/level-test/`). Дивіться також `README.md`.

## Що робить проєкт

12 коротких шахових задач «знайди найкращий хід» на інтерактивній дошці. Складність
підлаштовується під відповіді (правильно → складніша, помилка → простіша). Наприкінці —
один із п'яти рівнів, пояснення з двох речень і кнопка запису на безкоштовний пробний
урок (`BOOKING_URL`). Нічого не збирається й не зберігається.

## Структура файлів

```
index.html              увесь тест: HTML + CSS + скрипт (єдиний файл, що публікується)
tools/pick_puzzles.py   відбір задач із файлу бази Lichess (запускається вручну, офлайн)
README.md               короткий опис для власника
CLAUDE.md               цей файл
```

Усередині `index.html` (скрипт, ES5):
- блок `НАЛАШТУВАННЯ`: `BOOKING_URL`, `TOTAL_TASKS`, `START_RATING`, `STEPS`,
  `MIN_RATING`/`MAX_RATING`, `LEVELS`, `RESULT_TEXTS`;
- `PUZZLES` між маркерами `/* PUZZLES:START */` і `/* PUZZLES:END */` (зараз 93 задачі);
- логіка: `finishPuzzle` → `nextStep` (зсув цільової складності на крок із `STEPS`) →
  `computeLevelIndex` (оцінка = середнє з рейтингів останніх 4 задач і наступної цілі;
  якщо жодної задачі не розв'язано — завжди «Новачок»);
- дошка: `squareList`, `renderBoard` (ходи кліками); правила шахів — тільки через chess.js.

## Як запускається

Збирати нічого не потрібно, залежностей для встановлення немає.
- Локально: `python3 -m http.server 8000` у корені, відкрити `http://localhost:8000/`
  (або відкрити `index.html` напряму; потрібен інтернет для chess.js з CDN).
- Публікація: GitHub Pages, Source — *Deploy from a branch*, `main`, `/ (root)`.
- Оновлення задач (рідко): `python3 -I tools/pick_puzzles.py lichess_db_puzzle.csv.zst puzzles.js`,
  далі вміст `puzzles.js` вставити між `PUZZLES:START` і `PUZZLES:END`. Для `.zst` потрібен
  `pip install zstandard`. Базу брати з <https://database.lichess.org> (не комітити в репозиторій).

## Секрети

Не потрібні жодні: немає ключів, токенів, змінних середовища, бекенду. `BOOKING_URL` —
публічне посилання на сторінку запису, а не секрет. Не додавати в репозиторій нічого, що
ідентифікує відвідувача.

## Правила проєкту (не порушувати)

**Файли й код**
- Тест — **один файл `index.html`** (HTML, CSS і скрипт разом). Зовнішні залежності лише
  одна: шахова бібліотека з CDN (див. нижче).
- Власний JavaScript — класичний ES5: `var`, `function`, без стрілкових функцій
  (`=>`), без `let`/`const`, шаблонних рядків і класів. Це стосується лише коду, який
  пишемо ми; підключена бібліотека може бути будь-якою.
- Інтерфейс повністю українською. Адаптивний під телефон (перевіряти на ширині 375 px,
  без горизонтального скролу, клітинки дошки не менші за ~40 px).

**Задачі**
- Лише з відкритої бази Lichess (<https://database.lichess.org>, CC0), рейтинг приблизно
  від 500 до 2000. **Задачі не вигадувати й не редагувати вручну.** Оновлювати набір тільки
  через `tools/pick_puzzles.py` з реального файлу бази.
- У коді зберігати для кожної задачі: `id` (ID Lichess), `rating`, `fen` (до першого ходу
  суперника) і `moves` (правильна послідовність, перший хід — суперника).
- Після будь-якої зміни задач перевірити, що всі FEN коректні й усі ходи легальні
  (завантажити кожну через chess.js і зіграти `moves`; команда нижче).

**Логіка тесту**
- 12 задач. Правильна відповідь → наступна задача складніша, помилка → простіша
  (кроки в `STEPS`). Одна спроба на задачу, без підказок; правильність не показується
  користувачу («Відповідь прийнято»).
- Задача зарахована, лише якщо зіграно **всю** правильну послідовність; будь-який хід, що
  ставить мат, теж правильний.
- Ходи — тільки натисканням на клітинки (вибір фігури, потім цілі). Без перетягування.
- Старт: екран вибору «Дитина / Дорослий» і кнопка «Почати»; окрема кнопка «Ще не граю»
  одразу дає результат «Новачок».
- Рівні рівно такі: Новачок / Початківець / Середній / Впевнений / Сильний, пороги —
  0 / 700 / 1000 / 1300 / 1650 (змінюються лише на прохання власника).
- Результат: рівень, пояснення рівно з двох речень **без шахових термінів**, кнопка
  «Записатися на безкоштовний пробний урок» із посиланням `BOOKING_URL`.

**Бібліотека правил**
- Не писати власний рушій правил. Використовується chess.js **0.10.3** з jsDelivr із
  фіксованою версією та `integrity` (SRI). Версії 1.x не підходять: це ES-модулі.
  Якщо змінюєте версію, перерахуйте SRI з файлу пакета npm і перевірте, що сторінка
  працює.

**Приватність**
- Сторінка не збирає й не зберігає жодних персональних даних: без форм, cookie,
  `localStorage`/`sessionStorage`/IndexedDB, аналітики, пікселів, шрифтів із зовнішніх
  сайтів. Єдиний зовнішній запит — chess.js. Посилання на запис — звичайний `<a>` без
  параметрів, що ідентифікують користувача.

**Дизайн**
- Палітра: темно-синій `#1a2c54`, червоно-оранжевий `#d6401a` (кнопки; білий текст на ньому
  має контраст ≥ 4.5:1), світло-блакитний `#e8f2fc` / `#cfe5f8`.

## Як перевірити зміни

Перевірка задач (FEN і легальність ходів; у каталозі поза репозиторієм):

```
mkdir -p /tmp/chk && cd /tmp/chk && npm init -y && npm i chess.js@0.10.3
# check.js: прочитати блок між PUZZLES:START/END, для кожної задачі
# new Chess().load(fen) і зіграти кожен хід із moves (from, to, promotion)
node check.js /шлях/до/level-test/index.html     # очікується: помилок: 0
```

Перед завершенням зміни:
1. Проходження тесту в браузері (Playwright, вікно 375 px, мобільний режим): усі відповіді
   правильні → «Сильний»; усі помилкові → «Новачок»; змішаний сценарій; «Ще не граю».
2. Немає помилок у консолі, `localStorage`/`sessionStorage`/cookie порожні, зовнішній
   запит один (chess.js).
3. `grep -n "=>" index.html` нічого не знаходить (так само `let `, `const `, зворотні лапки).
4. `BOOKING_URL` заповнений реальним посиланням (зараз `https://www.yaroslavchess.com/appointment`;
   не вигадувати інше).
5. Гілка розробки тесту: `claude/chess-level-test-mgyk5h`; для окремих завдань власник може
   вказати іншу гілку. PR відкривати лише на прохання власника.
